# Benchmarking the Learnability of Aspect-Based Sentiment Analysis on Indonesian Protest Tweets

Data and code for the article *Benchmarking the Learnability of Aspect-Based Sentiment
Analysis on Indonesian Protest Tweets* (International Journal of Engineering, Science
and Information Technology). The deposit contains the adjudicated gold standard, the
annotation and adjudication artifacts behind it, and the complete benchmark pipeline:
fold construction, five lexical model families, the fine-tuned encoder, the zero-shot
comparator, the three validation designs, and every metric and paired test reported in
the paper.

Everything reproduces with the Python standard library plus scikit-learn, scipy and
openpyxl. Only the encoder needs torch.

## Repository layout

```
data/       gold standard, adjudication workbook, annotator files, raw comparator output
docs/       annotation and adjudication guideline, zero-shot prompt, reproducibility status
code/       the fifteen scripts of the pipeline
results/    per-record out-of-fold predictions, fold assignments, tables, run manifest
```

### Data

| File | Content |
| --- | --- |
| `data/28082026- Absa Final Gold Standar.xlsx` | **gold standard**: `index`, `text`, `relevant_gold`, `aspect_gold`, `label_gold` for all 7,131 records |
| `data/adjudication_analysis_results.xlsx` | per-record labels of the pre-annotator (GPT-4o-mini), the human validator, the independent annotator and the adjudicator, with `decision_rule` and `rationale`, plus the workload, disagreement-pattern and decision-rule sheets that back Section 3 |
| `data/(...) Anotasi part - 1..4.xlsx` | the four independent annotations collected without access to the model output (source of the agreement statistics) |
| `data/250626 - Human Validator Annotator_final version.xlsx` | validated annotation of the second stage |
| `data/result_annotation_gpt-4o-mini_20260417_120524.xlsx` | raw responses of the comparator, before de-duplication (7,157 rows, lowercase labels) |
| `data/human_effort_annotation_reduction_analysis.xlsx` | label retention, agreement and adjudication workload summaries, and the per-record flags |
| `data/gold_standard_analysis.xlsx`, `data/gold_standard_coverage_analysis.xlsx` | label distributions and gold-label coverage |
| `data/annotation_consistency_crosscheck_240826.xlsx`, `data/duplicate_text_records.xlsx` | consistency cross-check and the exact-duplicate pairs removed before annotation |

`data/derived/` holds artifacts produced by the pipeline (`near_duplicate_clusters.csv`,
`day_partition.csv`, `table8_feature_counts.csv`); they are regenerated by the scripts
below and are committed so that the fold inputs are inspectable without a run.

### Code

| Script | Produces |
| --- | --- |
| `code/run_benchmark.py` | **entry point**: fits the lexical models under the stratified, grouped and day-held-out schemes, writes `results/predictions/<scheme>_<task>_<model>.csv` (per-record out-of-fold predictions) and `results/folds/<scheme>_<task>.csv`; `--report-vocabulary` prints the feature counts of Section 3 |
| `code/neardup.py` | near-duplicate clustering (normalised word-trigram Jaccard >= 0.7) used by the reported audit and as the grouping key |
| `code/day_partition.py` | collection timestamp and collection day of every record, and the 24-hour window holding 88.8% of the corpus |
| `code/features.py` | the seven textual features with counts, error rates, complement rates and chi-square p-values (Table 8) |
| `code/make_tables.py` | Tables 3, 5, 6, 9 and 10 rebuilt from the saved predictions, with the self-check against the published values |
| `code/zeroshot.py` | comparator coverage and scoring (Table 6); `--query` re-runs the API configuration of Appendix A |
| `code/indobert_model.py` | fine-tuned `indobert-base-p1` on the **identical folds** (Table 3, and the fold-level contrasts of Table 9) |
| `code/folds.py`, `code/metrics.py`, `code/stats_tests.py`, `code/data_io.py`, `code/lexical_models.py`, `code/config.py` | fold builders, metrics incl. conditional/coverage-aware scoring, paired bootstrap + exact McNemar + Nadeau-Bengio t-test with Holm-Bonferroni, IO, model zoo, configuration |

## Reproducing

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python code/run_benchmark.py --report-vocabulary          # feature counts of Section 3
python code/neardup.py                                    # clusters -> data/derived/
python code/day_partition.py                              # timestamps, days, 24-h window
python code/features.py                                   # Table 8
python code/run_benchmark.py --schemes stratified grouped day_held_out \
       --tasks relevance aspect polarity                   # ~20 min, writes all predictions
python code/make_tables.py                                # Tables 3, 5, 6, 9, 10 + self-check
python code/zeroshot.py                                   # comparator coverage and scoring
```

Optional, only for the encoder (about 2.2 hours for all three tasks on Apple MPS,
~1.16 s per optimisation step at batch 32; with CUDA it is much faster):

```bash
pip install -r requirements-indobert.txt
python code/indobert_model.py --tasks relevance aspect polarity
```

Paths can be redirected with `ABSA_DATA_DIR` and `ABSA_RESULTS_DIR`; the seed (42) and
every hyperparameter live in `code/config.py`, mirroring Section 3 of the article.

## Reproducibility status

`docs/reproducibility_status.md` records, table by table, what the deposit reproduces
exactly and where the deposited code cannot reach the published number, with the reason.
In short: Table 3/4 (15 of 15 model-task cells), Table 6 (coverage and coverage-aware
scores) and all 15 contrasts of Table 9 reproduce exactly, the temporal row of Table 10
to within 0.006, while the near-duplicate audit count and four Table 8 feature rows
differ because the original detector lists are not part of the record and therefore had
to be re-implemented from the printed definitions.

## Notes

* **Coverage is part of the metric.** The comparator produces no label for some records;
  `conditional` scores are computed on the records it labelled, `coverage-aware` scores
  count the unlabelled records as errors. Both are reported side by side, and neither may
  be compared across the two without stating which one is in use.
* **Tweet text.** The deposit redistributes the post text as collected, for research and
  reproducibility purposes only; it remains subject to the platform's terms of service
  and to the rights of the original authors. No account names, profile information or
  network data are included.
